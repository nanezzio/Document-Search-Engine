# Document Search Engine

Проект на C++ и Qt для поиска по содержимому текстовых файлов. Индекс хранится в PostgreSQL. Обе программы собираются из одного проекта в Qt Creator и запускаются отдельно.

| Программа | Что делает |
| --- | --- |
| `indexer` | Обходит указанные папки и подпапки, считает слова в каждом файле и сохраняет результаты в PostgreSQL. |
| `searcher` | Принимает запрос в графическом окне, показывает подходящие документы, их релевантность и частоты слов. |

## Требования

- Компилятор с поддержкой C++17 и CMake 3.19 или новее.
- Qt 6.5 или новее с модулями **Core**, **Widgets**, **SQL** и драйвером PostgreSQL **QPSQL**.
- Запущенный сервер PostgreSQL и пользователь с правами создавать таблицы в выбранной базе.
- Qt Creator для сборки и запуска по инструкции ниже. Для редактирования окна можно открыть [mainwindow.ui](src/searcher/mainwindow.ui) в Qt Designer.

## Подготовка PostgreSQL

1. Подключитесь к своему серверу в pgAdmin.
2. Нажмите правой кнопкой по **Databases → Create → Database…** и создайте базу `document_search`. Если база уже есть, используйте её.
3. Скопируйте [config.example.ini](config.example.ini) в `config.ini` в корне проекта. В PowerShell это можно сделать командой `Copy-Item config.example.ini config.ini`.
4. Укажите в `config.ini` параметры подключения. Обе программы читают один файл настроек.

```ini
[database]
host=localhost
port=5432
name=document_search
user=postgres
password=

[indexer]
directories=test_documents
extensions=txt,md,ini,csv
```

| Параметр | Что указать |
| --- | --- |
| `host`, `port` | Адрес и порт сервера PostgreSQL. Для локальной установки обычно подходят `localhost` и `5432`. |
| `name` | Имя созданной базы данных. |
| `user`, `password` | Имя и пароль вашей учётной записи PostgreSQL. |
| `directories` | Одна или несколько папок через `\|`, например `C:/Documents\|D:/Notes`. Относительные пути считаются от папки с INI-файлом. |
| `extensions` | Расширения файлов через запятую. Текстовые файлы должны быть в UTF-8. |

При первом запуске индексатор создаёт таблицы внутри выбранной базы. В репозитории хранится `config.example.ini` с пустым паролем. Локальный `config.ini` исключён через [.gitignore](.gitignore).

## Сборка и запуск в Qt Creator

1. Откройте [CMakeLists.txt](CMakeLists.txt) через **Файл → Открыть файл или проект**.
2. Выберите комплект **Desktop Qt 6** и настройте проект. Для установленного комплекта MinGW выберите его вариант 64-bit.
3. В списке целей запуска рядом с зелёной кнопкой выберите **`indexer`** и нажмите **Ctrl+R**. В панели **«Вывод приложения»** появятся пути обработанных файлов и количество ошибок. После обработки индексатор завершается.
4. Переключите цель на **`searcher`** и снова нажмите **Ctrl+R**. Введите слова на вкладке **«Поиск»** и нажмите **Enter** или кнопку **«Искать»**.

В дереве проекта также видна цель `search_common`. Это библиотека с общим кодом, которую CMake собирает автоматически.

Программы ищут `config.ini` сначала в рабочем каталоге, затем в папке исходного проекта. Путь можно задать явно аргументом запуска `--config "C:/путь/к/config.ini"`.

## Как работает поиск

Индексатор открывает текстовые файлы из настроенных папок, приводит слова к нижнему регистру и считает частоту каждого слова в каждом документе. Пунктуация разделяет слова. Учитываются слова длиной от 3 до 32 символов. Результат записывается в три таблицы.

| Таблица | Что хранит |
| --- | --- |
| `documents` | Идентификатор и путь к каждому документу. |
| `words` | Идентификатор и текст каждого уникального слова. |
| `document_words` | Связь документа со словом и количество его вхождений в документе. |

Поисковик принимает до четырёх слов. SQL-запрос выбирает документы, в которых встречаются **все** слова запроса, и сортирует их по сумме частот. Например, если `привет` встречается два раза, а `мир` один раз, релевантность документа для запроса `привет мир` равна **3**. Поисковик обращается к базе, поэтому запросы не требуют повторного чтения файлов.

На вкладке **«Статистика»** кнопка **«Слова и частоты»** показывает суммарные частоты по всем документам. Кнопка **«Релевантность документов»** становится доступной после поиска и показывает оценки последней выдачи.

Повторный запуск `indexer` обновляет частоты для прочитанных файлов. Записи о файлах, удалённых с диска, остаются в базе.

## Проверка на тестовых файлах

Для проверки используйте пустую базу и оставьте `directories=test_documents`. В [тестовой папке](test_documents/) есть три файла, один из них лежит в подпапке.

| Действие | Ожидаемый результат |
| --- | --- |
| Запустить `indexer` | `Проиндексировано: 3, ошибок: 0`. |
| Выполнить поиск `привет мир` | Сначала `first.txt`, затем `subfolder/second.txt`. В `other.txt` есть только одно из двух слов, поэтому он не попадает в выдачу. |
| Открыть релевантность | У `first.txt` значение **3**, у `second.txt` **2**. |
| Открыть слова и частоты | `привет` — **4**, `мир` — **2**, `весна` — **1**. |
| Выполнить поиск `несуществующее` | Появится сообщение «Документы не найдены». |
| Повторно запустить `indexer` без изменения файлов | Частоты и порядок результатов останутся прежними. |

## Если программа не запускается

- **Файл настроек не найден.** Убедитесь, что файл называется `config.ini` и лежит рядом с `CMakeLists.txt`, или передайте его путь через `--config`.
- **Не удалось подключиться к PostgreSQL.** Проверьте в pgAdmin, что сервер запущен и база существует. Сверьте имя базы, порт, пользователя и пароль в INI.
- **QPSQL driver not loaded.** Проверьте, что драйвер QPSQL и клиентские библиотеки PostgreSQL доступны для выбранного комплекта Qt.
- **Поисковик сообщает, что таблица не существует.** Сначала запустите `indexer` с настройками той же базы.
